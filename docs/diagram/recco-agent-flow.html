Inside the Recco Agent

Every step between the text you send and the card on your TV, and the services that run each one.

AWS serviceOther service or library
1
The text arrives
You text the Recco number. The SMS provider calls a signed webhook on the API, which publishes the text to SNS. SQS holds it for intake.
UsesZernio SMSAWS LambdaLambda function URLAmazon SNSAmazon SQS
2
Intake sorts it out
An intake Lambda reads each text from the queue. Most texts are saved for the agent, and the TV shows a placeholder before the agent starts.
UsesAWS LambdaAmazon DynamoDBAWS AppSync Events
card.pendingPlaceholder on the TV in under a second
3
A worker starts the agent
Intake hands the text to a worker Lambda without waiting for it. The worker calls the agent on Bedrock AgentCore Runtime, with one session per text.
UsesAWS LambdaAmazon Bedrock AgentCore Runtime
4
The Recco Agent reads it
The agent waits 5 seconds for follow-up texts, because a link and its comment often arrive as two. Then the model works through four tools and calls save_cards once.
UsesBedrock AgentCore RuntimeVercel AI SDKVercel AI GatewayClaude Haiku 5.5OMDb APIScrapeCreatorsJina ReaderAWS Secrets Manager
5
save_cards checks the work and saves it
The checks that matter run in plain code, not in the prompt. Cards that pass are saved, and the TV swaps the placeholder for the finished card.
UsesTypeScriptAmazon DynamoDBAWS AppSync Events
card.readyThe finished card replaces the placeholder
